Score a transaction

Describe one payment and the model says how likely it is to be fraud, with its reasons. Two models look at it: one that learnt what normal payments look like and flags what it cannot explain, and one that learnt what known fraud looks like from labelled examples.

Customer history (the customer's previous payments)

The newest model judges a payment against this customer's own habits. Paste their previous payments as JSON, oldest first — a list of {"features": {...same field names...}, "secs_before": 3600} (or "ts" in epoch seconds). On your own installation you can instead give a customer id and the server remembers what it scores for that id; the public site keeps nothing.

Device details (what the device model sees)

What the browser or app reports about the device; a small model judges how risky the device looks on its own. Keys: os, browser, device_type, screen, session_length_min, keep_alive, phone_valid, email_domain, recipient_email_domain, name_email_similarity, account_age_days, foreign. Fields set in the form win.

Text on the payment (what the text models read)

Free text that came with the payment: url (judged by a model trained on malicious links), description / memo / message (one trained on scam postings), profile / bio (one trained on fake profiles). Each adds its own evidence to the verdict. None of the payment datasets carried text, so this never changed a reported number.

How the customer used the device (mouse, keystrokes, touch, motion)

Raw events from the session, which a set of models trained on public behaviour data compares with how this customer usually moves and types: mouse rows [t, x, y, kind], keystroke rows [t, key, down|up], touch rows [t, x, y, pressure, size, action], motion rows [t, x, y, z]. On your own installation a customer id lets the server build that customer's profile from their earlier sessions; the first session only enrols.

No transaction scored yet.

Fill in what you know and press Score transaction, or load an example. Fields you leave blank count as unknown, not as zero; the model was trained to cope with missing fields.

Score a whole spreadsheet instead

A CSV file using the field names from the How it works page (any subset). Every row gets a probability, a percentile and a flag at the alert budget above. If the file has an is_fraud column you also get the accuracy (AUROC and recall) on your own data.

Training data

Eleven public datasets of payments, translated into one common set of fields. Where a dataset has no such field it is marked unknown and the model skips it rather than guessing.
